# 开发与验收记录

本项目从原有实现继续开发，保留 Python、PySide6、SQLite 和本地视觉描述的架构。

## Mac 版适配与安装包流程（2026-11-12）

沿用现有 Python/PySide6、SQLite 与本地检索架构，新增 Mac 应用包、DMG 和校验文件的构建流程，并分别面向 Apple 芯片与 Intel 构建。固定 PySide6/Qt 与 Intel OpenCV 依赖要求 macOS 14+，较旧系统尚未开展依赖兼容验证。Mac 运行适配覆盖 Finder 定位、默认数据目录、中文字体及快捷键、从 Finder 启动时的 Ghostscript 发现和平台提示。详细安装、权限、共享卷及构建步骤见 [Mac 版说明](MACOS.md)。

构建流程在 macOS 上运行固定依赖的源码回归，并从复制后的 `.app` 内调用冻结程序自测，检查核心依赖、真实 Qt 窗口、PNG/PSD/PSB/PDF/AI 整图与局部检索、索引持久化及原文件哈希；同时检查应用二进制架构、实际最低系统要求和 DMG 只读挂载。升级、移除应用、重新复制后，验证独立索引仍可复用。默认仅为 ad hoc 签名；Developer ID 与 Apple 公证需要构建机已有证书和配置。

本次在 Linux x86_64、Python 3.12.14 环境运行完整回归：**106 passed in 27.45s，无失败或跳过**。包括 Finder 参数、Mac 数据目录、受限 PATH 下的 Ghostscript 发现、菜单退出取消线程，以及从真实 Mach-O 加载命令推导最低系统要求。源码自测通过 PNG/PSD/PSB/PDF/AI 共 5 文件、7 页的整图与局部检索。`pip check`、Shell 语法检查、Python 编译检查及 `git diff --check` 均通过。

当前开发会话使用 Linux，不能生成或运行原生 `.app`；本次 Linux 回归与 macOS 工作流实际结果须分别记录。只有在对应架构 macOS 工作流通过后，才能把该运行的 DMG 视为经过自动化验证的安装包。

目标 Mac 仍需验收 Finder 双击启动、系统权限与 Gatekeeper 提示、Finder 定位、真实文件拖放、取消/退出、实际 Adobe 文档、外置磁盘和公司共享卷。未验证的事项不能由模拟平台测试或 Linux Qt 无显示服务器检查代替。

## 0.2.0 局部截图检索（2026-11-09）

新增独立的“局部截图检索”模式，保留整图检索及原有扫描、增量更新、取消、文件定位、路径复制、目录打开和 CSV 导出。局部定位使用 OpenCV SIFT、受约束的缩放/平移估计、全区域像素/颜色校验和多尺度模板回退；不依赖在线服务。结果返回页面/画板内的归一化区域，缩略图和大预览显示红框，CSV 添加四个边界坐标列。

数据库只增加 `partial_pages` 缓存表，使用页面外键级联失效。保留已有文件 ID、路径、根目录关联、SHA-256、整图描述、缩略图和画板标签。旧缓存首次使用时按文件补齐；同一文件所有缺失页面在一个事务内提交，取消或源文件变化时回滚，不改写旧索引记录。重开后直接复用缓存。新扫描生成局部缓存，重新扫描和移除索引时清除对应旧缓存。缓存损坏时从原文件重新生成。

新增回归覆盖非中心/贴边裁剪、0.55–2.3 倍缩放、JPEG 压缩、低纹理绘图、无关图片/纯色/错误颜色拒绝、逐阶段取消；真实 PSD/PSB 多画板（有/无合成预览）、PDF 第二页、PDF 兼容 AI、EPS 和旧版 AI；旧库记录与原文件不变、重复检索不重渲染源文件、跨页面取消回滚、查询/源文件变更时不返回旧区域、缓存失效与重建；真实 Qt 工作线程检索、红框预览、CSV 边界坐标及切回整图检索。

实际验证环境：Linux x86_64、Python 3.12.14、OpenCV 4.14.0、Ghostscript 10.05.1、Qt 无显示服务器模式。

```bash
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/workspace/.cache/image-tools/qt .venv/bin/python -m pytest -q -ra --junitxml=/tmp/image-tools-partial-regression.xml
```

**结果：92 passed in 17.17s，退出码 0，无失败或跳过。** 保留原有 68 项覆盖并增加局部检索及交互回归，也检查了素材库含单像素宽图片时不会中断其他候选检索。`pip check`、CLI `--help` / `--version`（0.2.0）及 `git diff --check` 通过。实际渲染并检查了包含截图、两项局部命中红框的主界面和放大预览。

另外使用 Pillow 官方仓库中的 `Tests/images/hopper.jpg` 照片，在 3 个裁剪位置（含贴边）和 0.6、1.4、2.3 倍缩放下执行 9 次定位，全部命中。该下载样本未加入仓库，不代表用户全部实际素材都已验收。

Windows EXE 打包、原生文件管理器行为和用户实际大型素材库仍需在目标 PC 上验收。截图应仅含图片内容；纯色/重复纹样、过小细节、旋转、透视和非等比拉伸不保证匹配。坐标对应最长边不超过 1600 像素的页面/画板预览，不是 Adobe 文档的绝对画布坐标。

## 0.1.1 多画板修复（2026-11-06）

原实现只为 PSD/PSB 整图建立一份视觉特征。多个画板与留白混在同一预览时，单个画板的导出图片无法得到可靠的对应匹配。

本次增加每个可见画板的独立预览和特征；在可用的整图预览中按原始分辨率裁切，画板相互重叠、位于文档画布外或无合成预览时，改用画板单独合成。普通图层不会变成独立检索目标，隐藏画板不参与检索。结果和 CSV 保存并显示最佳匹配画板的名称。

数据库采用增量迁移，保留已有记录；再次扫描时只对旧版 PSD/PSB 索引强制更新画板特征，其他未变化格式仍可跳过。针对共享盘，同一文件的多个页面/画板共用一次文件状态检查。

实际执行：

```bash
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/tmp/image-tools-qt-cache .venv/bin/python -m pytest -q
```

**结果：68 passed in 13.31s，退出码 0，无失败或跳过。** `pip check` 和 `git diff --check` 也通过，CLI 版本显示 `0.1.1`。

新增 14 项测试：9 项渲染（PSD/PSB、有/无合成预览、正/负画布外坐标、重叠画板、原始分辨率裁切、超过 20 个画板及可见性）；4 项索引（PSD/PSB 导出图检索与标签恢复、旧数据库迁移及定向重建、路径状态检查次数）；1 项桌面结果显示与 CSV 导出。

这些测试读取和写入真实 PSD/PSB 格式的程序生成样本。用户具体的问题文档、Windows 本机的新版本 EXE，以及公司实际共享盘的连接和性能尚未验证。复杂 Adobe 效果与超大文档仍受下述预览器限制；可以使用一个可分享的实际多画板文件及对应导出图做进一步回归。

升级后需点击一次“建立 / 更新索引”，无需删除索引。PDF/AI/TIFF 的默认 20 页限制保持不变，PSD/PSB 的可见画板不受该页数限制。

## 0.1.0 历史验收

### 已完成工作

- PSD/PSB 在解析图层前校验文件头及尺寸，保留无合成预览时的图层合成能力。
- EPS 渲染锁定输出尺寸，防止源文件的页面设置突破缩略图大小限制。
- 查询文件在检索期间发生变化时停止返回结果，避免使用过期哈希。
- 扫描失败且源文件同时发生变化时丢弃不可信的哈希；跳过目录符号链接及 Windows 目录联接。
- 取消检索不再显示失败弹窗；更换查询图片会清除旧结果及旧名单导出状态。
- 查询选择器与扫描器使用同一格式列表，包含 AVIF、JFIF、JPE。
- 无法读取预览时，明确提示只进行了文件内容比对，没有进行相似图片检索。
- Windows 启动脚本增加 Python 版本与组件检查，修复依赖可安装但无法导入时反复安装的循环。

### 尚未验证与已知边界

- 没有在 Windows 真机上运行。资源管理器调用和目录联接检测使用模拟测试，未声称已验证原生行为。
- 已提供 `build-windows.bat`，但尚未在 Windows 生成或验收 EXE。Linux 不能替代这一步。
- 当前文档测试包含真实文件格式的生成样本，不代表所有 Adobe 文档特性都得到支持。复杂图层、字体、链接资源和色彩配置可能影响预览。
- 大型 PSD/PSB 的总图层数据仍可能占用较多内存；画布限制不是总内存限制。取消需要等待当前预览步骤结束。
- PDF/AI/TIFF 默认仅索引前 20 页，可通过 `--max-pages` 调整后重新扫描。0.1.1 新增的 PSD/PSB 可见画板不受该限制。相似检索是外观匹配，不证明源文件的实际来源。

Windows 验收顺序：运行 `start-windows.bat` → 添加实际素材目录并扫描 → 查询图片 → 查看相似文件和源文件候选 → 使用资源管理器定位 → 导出 CSV → 关闭并重新打开确认索引保留。需要 EPS/旧版 AI 时安装 Ghostscript 后重新扫描失败文件。
