# 图迹 · Image Tools

在自己的 Windows 或 Mac 电脑上，以图片查找本地的相同图片、外观相近图片，以及画面匹配的 PSD、PSB、AI、EPS、PDF 源文件候选。也可以用任意位置的局部截图查找包含它的完整图片或画板。结果包含缩略图、文件名、完整路径和匹配页，可直接在资源管理器或 Finder 中定位文件。

图片、缩略图和索引均留在本机。首次安装下载软件依赖；使用时不需要账号、联网服务或 API 密钥。

## 在 Windows 上使用

### 安装包（无需安装 Python）

在本仓库的 [Releases](https://github.com/thearningwong-arch/image-tools/releases) 中下载 `ImageTools-版本号-win-x64-setup.exe`，双击后按中文向导安装，完成后从桌面或开始菜单打开“图迹”。适用于 Windows 10/11 64 位；安装到当前用户目录，不需要管理员权限。安装包内置 Python、Qt 及图片检索、PSD/PSB、PDF 兼容 AI 所需依赖，安装后可离线使用。

升级时直接运行新版安装包。现有索引继续位于 `%LOCALAPPDATA%\ImageTools`，升级、在 Windows“已安装的应用”中卸载、以及重新安装均保留该目录；原素材文件也不会被删除。若以前用源码版，使用同一 Windows 账号和默认索引目录即可沿用；自定义索引目录需继续使用 `--data-dir` 或 `IMAGE_TOOLS_DATA_DIR`。

EPS / 旧版 PostScript AI 仍需下文的可选 Ghostscript，不包含在安装包内。安装文件尚未做商业代码签名；Windows 可能显示未知发布者。请从本仓库 Releases 下载，并可用附件 `.sha256` 核对文件。

### 从源码运行（开发者）

1. 安装 **64 位 Python 3.12–3.15**（建议 3.12/3.13），安装时勾选 **Add Python to PATH**。
2. 把本项目解压到本机文件夹，双击 **`start-windows.bat`**。首次启动自动建立独立环境并下载依赖，需要联网。
3. 添加存放图片/设计文件的文件夹，点击建立或更新索引，等待扫描完成。
4. 选择或拖入一张参考图片，选择“整图相似检索”或“局部截图检索”，点击“开始检索”。可调整匹配分数门槛，或导出结果 CSV。
5. 点击结果的“定位文件”按钮，即可在资源管理器中打开所在目录并选中文件。也可以复制路径或打开文件夹。

以后双击同一启动文件即可使用。文件有新增、修改、移动或删除时，需要重新扫描；没有变化的文件会跳过。第一次扫描大型素材库可能需要较长时间，可取消后再继续。取消会等待当前预览处理步骤结束，复杂源文件可能需要稍等。

若使用命令行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m image_tools
```

## 在 Mac 上使用

Mac 版沿用相同的本地索引、整图/局部截图检索、源文件预览和 CSV 导出。当前固定依赖要求 **macOS 14 或更新版本**。提供 Apple 芯片（`arm64`）和 Intel（`x86_64`）两种独立构建；在苹果菜单“关于本机”中确认机型后选择对应版本。

构建通过后生成 DMG 安装镜像和 `.sha256` 校验文件。打开镜像，将 `ImageTools.app` 拖到“应用程序”，推出镜像后从“应用程序”打开图迹；使用安装包不需要另外安装 Python。当前分支补齐了 Mac 构建流程，是否已有可下载安装包及原生测试结果，以 [Actions](https://github.com/thearningwong-arch/image-tools/actions) 和 [Releases](https://github.com/thearningwong-arch/image-tools/releases) 中的实际产物为准。

Mac 索引位于 `~/Library/Application Support/ImageTools`。替换或移除应用会保留此目录及原素材；升级前关闭图迹再替换应用。首次访问桌面、文稿、下载、外置磁盘或网络卷时，按 macOS 提示授权。Finder 已挂载并可读取的共享卷可以添加为素材目录。

开发者可在 macOS 14+ 安装 Python 3.12–3.15 后双击 `start-macos.command` 从源码运行，首次启动会创建独立环境并安装依赖；也可使用下文命令。在 Mac 构建机上运行 `bash scripts/build_macos.sh`（或双击 `build-macos.command`）生成安装镜像。签名、公证、Ghostscript、权限与完整验收步骤见 [Mac 版安装与构建说明](docs/MACOS.md)。

## 支持范围

| 文件类型 | 检索方式与条件 |
| --- | --- |
| JPG/JPEG、PNG、WebP、BMP、GIF、TIFF 等 | 读取图像预览；按 EXIF 纠正方向，透明背景按白色处理 |
| PSD、PSB | 保留可用的整图预览，并为每个可见画板单独建立索引；结果显示命中的画板名称。建议在 Photoshop 保存时开启“最大兼容性” |
| PDF | 渲染页面预览，不需要安装 Acrobat |
| AI | 含 PDF 兼容数据的 AI 直接渲染；建议 Illustrator 保存时勾选“创建 PDF 兼容文件” |
| EPS、旧版 PostScript AI | 需要额外安装 Ghostscript；未安装时会列出明确失败原因 |

PDF、PDF 兼容 AI 和 TIFF 默认最多索引前 **20 页**，普通动图取第一帧。可用以下方式增加页数，随后重新扫描：

```powershell
.\start-windows.bat --max-pages 100
```

**PSD/PSB 的可见画板不受上述 20 页上限限制。** 画板从原始分辨率的合成预览中裁出；没有合成预览、画板相互重叠或超出文档画布时，尝试单独合成画板。保留画板背景与留白，不把普通图层当作独立画板。隐藏画板不参与外观检索。

从 0.1.0 升级到 **0.1.1** 后，打开程序并点击一次“建立 / 更新索引”。数据库会自动补充画板标签字段，旧 PSD/PSB 会重新提取特征；无需删除旧索引，未变化的其他格式继续跳过。检索结果和导出的 CSV 都包含匹配画板名称。以 PSD/PSB 本身作为查询文件时使用整图预览；没有整图时取首个可见画板。查找某个画板的源文件，建议用该画板的导出图片作为查询。

无法读取、加密、损坏或超过预览资源限制的文件会进入扫描问题列表，不能参加外观相似检索；仍可通过完全相同文件的 SHA-256 查找副本。预览器会限制约 1 亿像素以上的超大图片/PSD 解码，Pillow 的内存保护还可能提前拒绝处理；可单独导出较小预览后检索。PSB 文件体积本身不代表一定可读取，仍受图像尺寸与文档特性限制。部分 Photoshop 效果、颜色配置、链接资源和复杂 AI/EPS 的预览可能与原软件不同。

**安装 Ghostscript（可选）**：从 [Ghostscript 官网](https://ghostscript.com/releases/gsdnld.html) 安装 Windows 64 位版本。程序会尝试从 PATH 或标准安装目录发现 `gswin64c.exe`。自定义安装位置可在启动前设置：

```powershell
$env:IMAGE_TOOLS_GHOSTSCRIPT = 'C:\Program Files\gs\gs10.xx.x\bin\gswin64c.exe'
.venv\Scripts\python.exe -m image_tools
```

安装后重新扫描失败文件即可，不需要重建整个素材库。

## 局部截图检索（0.2.0）

1. 添加素材文件夹并建立索引；已经有索引的用户直接沿用原目录和数据，不要删除数据库。
2. 选择或拖入一张**只包含图片内容的局部截图**，将“检索方式”切换为“局部截图检索”，点击“开始检索”。截图可以来自原图的边角或其他非中心位置，也可以经过等比例放大、缩小或常见 JPEG 压缩。
3. 结果中的红框标出截图在完整图片、匹配页面或画板中的位置。点击“查看命中区域”查看较大预览；定位文件、复制路径、打开文件夹和导出名单仍可使用。

PSD/PSB 按每个可见画板独立匹配，并保留画板名称。红框坐标以**命中的页面/画板预览**为参照，不是 Photoshop 整体画布的绝对坐标；多画板文件只显示最佳命中。PDF、PDF 兼容 AI、TIFF 仍遵守 `--max-pages` 页数设置，EPS/旧版 AI 仍需要 Ghostscript。

升级只会新增局部检索缓存表，不改写旧索引中的路径、文件哈希、整图特征、缩略图或画板标签。新扫描会保存局部特征；旧索引在第一次局部检索时自动读取源文件并补齐缓存，以后重复检索复用缓存。首次检索可能较慢，尤其是共享盘或多画板源文件。取消时，已完成文件的缓存保留，当前文件未完成的缓存回滚；整图检索继续可用。源文件变化、移除索引或重新扫描时，相应局部缓存会失效。局部预览与特征存储在原有本机 SQLite 数据库中，会增加索引的磁盘占用。

CSV 保留原有列，增加“命中左/上/右/下边界（0-1）”四列；局部命中填写归一化坐标，整图模式留空。例如左边界 0.25 表示页面/画板宽度的 25% 处。

该模式使用本地局部特征、几何校验和多尺度像素验证，不需要模型下载或联网识图。截图至少需 **16 × 16 像素**并包含可辨图案。预览最长边为 1600 像素：原图中的极小细节可能已在预览中丢失。纯色、重复纹样、严重模糊、极大缩放、旋转/透视变形、非等比例拉伸，以及截图混入窗口边框等内容时，可能无法可靠定位。分数用于筛选候选，不是匹配概率或源文件归属证明；降低门槛也不会取消必要的几何和像素验证。

## 如何理解结果

- **文件完全相同**：文件的 SHA-256 相同，即字节内容一致；文件名可以不同。
- **预览一致**：本工具渲染出的可见画面像素一致，文件格式、图层或元数据可能不同。
- **外观相似**：使用感知哈希、多尺度裁剪和颜色信息进行近似匹配。可找到缩放、压缩、轻微改色及部分轻度裁剪版本。分数是排序指标，**不是匹配概率**。
- **局部截图命中**：局部模式在完整页面或画板中找到了经验证的截图区域，并以红框标注。

默认门槛为 70，可降低门槛寻找更多候选。程序按文件列出最佳匹配页面或画板，最多显示 100 个结果。与 PSD/AI 等源文件的画面相似，只能说明它是候选，不能证明该图片一定由此源文件导出。这里没有“同类物体/同种风格”的语义模型；整图模式无法可靠匹配严重裁剪或嵌在复杂版面里的小图，这类情况应使用局部截图模式。旋转、大面积改版、纯色和重复图形仍可能漏报或误报。

## 索引与原文件

- Windows 默认索引位置：`%LOCALAPPDATA%\ImageTools`；Mac 为 `~/Library/Application Support/ImageTools`。目录包含 SQLite 数据库及 JPEG 缩略图。
- 添加和移除索引文件夹均不会移动、修改或删除原文件。
- 支持多个文件夹和重叠目录，结果不会因重复扫描同一路径而重复列出。
- 磁盘或网络共享离线时保留已有索引；扫描问题列表会提示不可访问。失效路径无法在资源管理器或 Finder 中打开，磁盘恢复后可重新扫描。
- 索引含文件路径和缩略图，需要清除时先关闭程序，再删除索引目录。无需删除素材。
- 可使用 `--data-dir D:\ImageToolsIndex`，或环境变量 `IMAGE_TOOLS_DATA_DIR` 更改索引位置。

扫描基于文件大小和纳秒修改时间判断变更，未做文件系统实时监听。搜索会对已索引预览做本地比较；当前版本适合个人素材库，超大规模库还需要向量索引和性能优化。

## 公司网盘 / 共享盘

资源管理器可以读取的映射盘（如 `Z:\设计素材`）和共享路径（如 `\\服务器\共享\设计素材`）可以作为素材目录：

1. 使用运行图迹的同一 Windows 账号，在资源管理器中打开该目录，完成公司网络/VPN连接和共享盘登录。
2. 在图迹“添加文件夹”的选择窗口中选择盘符，或粘贴完整共享路径。可以先选择一个小的项目目录验证。
3. 建立索引后照常查询、导出名单和在资源管理器中定位文件。建议保持 SQLite 数据库与缩略图在本机默认目录。

图迹复用 Windows 的共享盘访问权限，不需要把公司账号密码填入程序。映射盘符需要在当前运行账号下可见；使用普通权限启动图迹即可，若看不到盘符，可尝试完整共享路径。

首次扫描需要读取源文件，速度取决于网络、文件大小及画板数量。后续更新跳过未变化的文件；搜索同一个多页/多画板文件只检查一次路径状态。文件变化仍需要手动更新索引。断网时保留已有索引，但当前不可访问的文件不会出现在检索结果中；重连后可重新搜索或更新。网络请求受 Windows 超时机制影响，取消操作可能需要等待当前文件读取结束。

本版本未连接用户的公司网络进行实测，因此不能保证特定网盘产品、权限配置或大型素材库的性能；浏览器网页型网盘不属于这一接入方式。

## 自定义界面设计

可以用 Photoshop 提供设计稿，再按稿实现桌面界面。建议提供分层 PSD、各界面的 PNG 参考图、独立图标/图片、字体信息和交互说明。无需把普通文字、按钮和表格切成图片。具体清单见 [UI 设计稿交付说明](docs/UI_DESIGN.md)。

## 打包为 EXE

在 **Windows 构建机**安装 64 位 Python 3.12 和 Inno Setup 6.5 或更新版本，双击 `build-windows.bat`。简体中文语言资源已随仓库提供。脚本安装固定版本依赖、运行回归测试、用 PyInstaller 打包运行时，再生成 `dist\ImageTools-版本号-win-x64-setup.exe`。普通用户只需要这个安装文件，不需要 Python 或 Inno Setup。详细构建及验收方法见 [Windows 安装包说明](docs/WINDOWS_INSTALLER.md)。

仓库的 Windows installer 工作流在 Windows 机器上构建、运行应用回归、安装真实旧版再升级、运行安装后的 EXE，并检查卸载及重装保留索引。通过后上传安装文件；推送与应用版本一致的 `v版本号` 标签时，再自动发布到 Releases。构建和验收报告保留在对应 Actions 运行中。Windows 10/11 实际用户电脑上的原生文件管理器、公司共享盘和大素材库仍需目标环境验收。

## 开发与验证

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m image_tools
```

Linux 无显示服务器时使用 `QT_QPA_PLATFORM=offscreen` 运行 UI 自动化检查。运行桌面界面需本地显示会话。macOS 使用 Finder 定位，Linux 打开所在目录。Mac 原生安装包需在对应架构的 Mac 上构建和验证；Linux 检查不能替代这一步。

代码分为 `rendering.py`（文档预览）、`features.py`（整图描述与比较）、`partial.py`（局部定位与多尺度验证）、`library.py`（SQLite 增量索引与检索）、`ui.py`（桌面交互）和 `platform_utils.py`（文件管理器操作）。测试包括真正的文档渲染、索引更新/删除/取消、相似与局部检索、旧索引兼容和桌面工作流。

0.2.0 历史验证为 **92 项测试通过，无失败或跳过**。Mac 版新增流程与本次实际验证结果见 [开发与验收记录](docs/VALIDATION.md)。
